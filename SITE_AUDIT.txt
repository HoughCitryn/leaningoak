Leaning Oak Ranch: live-site comparison and SEO audit
Audit date: September 30, 2026
Live source: https://www.leaningoakranch.com/

RESULT

The goal is to preserve the live site's current information and improve its
presentation, accessibility, SEO, and contact workflow. Pixel-for-pixel duplication
is not required. All six current pages are retained, both original gallery
collections are complete, and all nine live sitemap URLs now have a relevant
destination. The user chose to consolidate obsolete pages through redirects.
Outdated package terms and 2017-2018 calendar images are intentionally not
presented as current information. Nothing was deployed to the live site.

SCOPE AND METHOD

Read the live robots file and sitemap index, then fetched every one of the nine
page URLs in the live page sitemap. Compared HTML, headings, metadata, links,
image inventories, and form markup against the local source and production
HTML. Tested the local production server's page and metadata endpoints,
redirects, 404 response, and invalid inquiry response.

Live inventory: https://www.leaningoakranch.com/page-sitemap.xml
Live robots: https://www.leaningoakranch.com/robots.txt

No connected browser was available. This is a source/content/HTTP audit, not a
desktop/mobile screenshot comparison. Pixel alignment, interactive behavior
in a real browser, Lighthouse scores, and field Core Web Vitals remain unverified.
All live image counts below are deduplicated because the WordPress HTML contains
separate responsive copies of some sections.

SHARED DIFFERENCES

The local header, footer, consent UI, button styling, spacing, responsive CSS,
and Next.js image handling differ from the WordPress/Divi implementation.
Navigation destinations for the five main pages and the business contact
details are retained. Metadata and structured data were intentionally improved
in the rebuild and should not be copied back from weaker live metadata simply
to achieve a source-code match.

SEO STATUS AFTER CHANGES

All six indexable local pages have unique titles and descriptions, one H1 in
main content, H2/H3 headings without skipped levels, self-referencing HTTPS/www
canonical URLs, matching Open Graph metadata, Twitter sharing metadata, and
parseable JSON-LD. Image alt attributes are present, and referenced image files
exist. Empty alt text is retained on decorative images. Structured-data syntax
was checked; Google rich-result eligibility was not certified.

Heading levels describe actual sections/subsections; adding heading counts
alone is not a ranking guarantee. The H3 requirement here follows this project
request, not a universal search-engine requirement.

Existing sitemap.ts and robots.ts were already present. Their served responses
were verified at /sitemap.xml and /robots.txt with HTTP 200 and appropriate
content types. The sitemap now derives its six URLs from the shared SEO data.
The three legacy redirects are excluded from this indexable inventory.
Robots permits public-page crawling, excludes /api/, and declares both sitemaps.
The existing image sitemap was expanded to include all six page routes and the
complete venue/gallery collections, feature photos, and gallery/privacy heroes.

Also verified:
- /image-sitemap.xml serves valid XML and all referenced media files exist.
- Legacy WordPress sitemap endpoints redirect permanently to /sitemap.xml.
- Non-www or HTTP production-host requests redirect to HTTPS/www.
- Missing pages return HTTP 404 with noindex.
- The Open Graph image endpoint returns an image successfully.
- The unwanted Vercel starter favicon was removed. The existing ranch icon is
  retained, and /favicon.ico redirects to that same branded asset.
- Home and venue descriptions were shortened to avoid unnecessarily long copy.

CONTACT EMAIL CONFIGURATION

.env.example now documents SMTP_HOST, SMTP_PORT, SMTP_SECURE, SMTP_USER,
SMTP_PASS, SMTP_FROM_EMAIL, and CONTACT_TO_EMAIL. Copy it to .env.local and
provide your email provider's values. No real SMTP credentials were added.

The contact endpoint now supports SMTP through Nodemailer. A configured host
selects SMTP; a blank SMTP_HOST retains the existing Resend option. STARTTLS
is required for non-implicit-TLS SMTP connections. The visitor is Reply-To,
and the destination is configured server-side. Invalid configuration or rejected
delivery returns an error, not a success message. Timeouts bound external calls.

Both Turnstile keys must also be set. Public variables must be set before the
production build. Without the public key, the form remains disabled and offers
phone/email contact instead of showing implementation instructions to visitors.
No real email was sent and no CAPTCHA was completed during verification.

VALIDATION

pnpm verify checks ESLint, TypeScript, 24 inquiry tests, the production build,
84 archived media assets, internal links, and the production-HTML SEO audit.
The added command pnpm check:seo can be rerun after any production build.
SMTP tests mock the mail provider; actual delivery still requires configured
credentials and an end-to-end delivery check in the deployment environment.

REMAINING FOLLOW-UP

The original live gallery collections and current primary-page information are
retained. Legacy pages are intentionally consolidated as selected by the user;
outdated package terms and historical availability images are not copied into
current offers. Text is edited for clarity rather than reproduced verbatim.
Layout differences are expected improvements, not content-migration failures.

Measure performance in a real browser before launch. In particular, large CSS
hero background images are not automatically optimized by next/image. This
audit does not establish a Lighthouse or Core Web Vitals score.

After deployment, verify the public-domain responses again and submit the
sitemap in the site's Search Console account. Indexing, backlinks, search
rankings, and account-level Search Console configuration were not inspected.
